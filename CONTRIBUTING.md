# Contributing to RiftX

Thank you for helping improve RiftX. Contributions should preserve its Pentest-first,
explicit-authorization, fail-closed safety model.

## Before opening an issue

- Use GitHub Issues for reproducible RiftX defects and scoped feature requests.
- Use the private process in [SECURITY.md](SECURITY.md) for vulnerabilities.
- Do not include credentials, real target details, captured traffic, or generated reports.
- Confirm the behavior still exists on the latest `main` branch.

## Development setup

RiftX requires Python 3.12. Web development uses Node.js 26 and pnpm 10.32.1.
The repository's documented Agent-related verification commands use a Conda environment
named `agent`; an equivalent isolated Python 3.12 environment may be used by human
contributors.

```bash
python -m pip install -e ".[dev]"
pnpm install --frozen-lockfile
```

Use `riftx onboard` for local configuration. Docker is not required. A local Temporal
CLI is needed only for a live local stack started with `riftx start`.

## Required checks

Run the checks relevant to the change. Before requesting final review, run the full set:

```bash
python -m ruff check src/riftx tests migrations
python -m pytest
python scripts/qa/release-gate.py

pnpm --filter @riftx/web typecheck
pnpm --filter @riftx/web test
pnpm --filter @riftx/web build
git diff --exit-code -- src/riftx/_webui
```

The bundled WebUI under `src/riftx/_webui` is generated by the Web build and must be
committed whenever its source changes.

## Pull requests

- Keep one coherent change per pull request.
- Explain the affected trust, authorization, execution, evidence, or stop boundary.
- Add executable evidence for behavior changes.
- Update both `README.md` and `README_ZH.md` when user-facing instructions change.
- Preserve unrelated work and avoid committing local configuration or runtime state.
