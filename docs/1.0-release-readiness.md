# RiftX 1.0 Release Readiness

> Review date: 2026-07-28. This document separates repository implementation from external release evidence. A milestone is not complete until every exit condition in `1.0 计划.md` has evidence.

## Current verdict

**REQUEST CHANGES — do not publish `1.0.0` yet.**

The repository contains the main M0-M6 product path and the local implementation of most M7 build and supply-chain controls. M7 has not met its exit conditions because signed/notarized multi-platform artifacts, clean-system installation evidence, and a real release-workflow run do not exist. M8 now has repository-side dual-protocol live tool-loop and evidence-validation harnesses, but no RC execution evidence exists; required remote CI, protected live-provider runs, and the human acceptance matrix remain pending.

## M7 repository implementation

Implemented locally:

- Rust `1.95.0`, Node `22.20.0`, pnpm `10.33.0`, and Tauri dependency versions are pinned and machine-checked.
- Cargo and pnpm lockfiles are used in locked/frozen CI paths.
- RustSec auditing uses exact, expiring exceptions in `security/rustsec-exceptions.toml`.
- Rust and Node license reports are checked against the release allowlist.
- Production Node dependencies pass the configured high-severity audit gate.
- CycloneDX SBOM generation is configured in CI/release workflows.
- Release payload scanning rejects secrets, internal endpoints, debug/request dumps, symlinks, and development directories.
- Linux reproducible tarball packaging includes `riftx`, `riftxd`, license/notice files, install instructions, example configuration, build metadata, and SHA-256.
- A manual, protected `.github/workflows/release.yml` builds all platforms from one resolved tag commit and creates a draft release.
- The release workflow is draft-only; final publication requires a separately verified M8 acceptance record.
- The protected provider workflow validates both capability probes and execution-bound Responses/Chat Runtime tool loops without uploading raw transcripts.
- `scripts/riftx/verify-release-acceptance.py` rejects incomplete, cross-commit, duplicate, or non-Go M8 evidence.
- Desktop hardened runtime is enabled; macOS and Windows signing/notarization commands are part of the protected workflow.
- Product versions report `1.0.0` consistently from Desktop, Tauri, CLI, daemon, and the About view.
- `SECURITY.md` and `architecture/threat-model-1.0.md` define support, disclosure, response targets, and residual security boundaries.
- Legacy configuration and SQLite State DB upgrades create adjacent pre-1.0 backups; the DB schema update is transactional and newer schemas fail closed.
- `docs/release/upgrade.md` defines the supported forward upgrade and backup-based RC rollback boundary.

## Disk hygiene

Large local growth was caused by two independent Rust build trees (`codex-rs/target` and `apps/desktop/src-tauri/target`) containing duplicate debug objects and heavy V8, AWS, TLS, SQLite, and Tauri dependencies. They are reproducible build outputs, not source data.

Run the recommended cleanup after local validation:

```bash
conda run --no-capture-output -n agent just clean-riftx-generated
```

The command removes only the two Rust `target` directories and generated Desktop `riftxd-*` sidecars. It preserves source, lockfiles, `.gitkeep`, reports, artifacts, state databases, and `node_modules`.
