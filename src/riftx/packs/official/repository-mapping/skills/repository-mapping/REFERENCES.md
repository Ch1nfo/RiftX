# Repository Mapping References

- Repository shape is evidence, not proof of runtime behavior.
- Generated, vendored, fixture, and test code must remain distinguishable from first-party production logic.
- Framework identification should be supported by manifests, imports, configuration, symbols, or entrypoint conventions.
- Unsupported, oversized, binary, and truncated regions are coverage gaps, not empty results.
- The repository map is a reusable planning artifact and must not itself promote vulnerability findings.
